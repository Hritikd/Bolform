## Conversation correctness

Keep the validated form schema, current values, latest user utterance, current question, and a small recent history available to the model. Request a structured result with proposed field patches, evidence from the latest utterance, ambiguity/confirmation requests, and one short localized reply. The server owns validation and completion state.

- Update only known field IDs. Missing keys mean leave unchanged; clearing a value requires an explicit user request.
- Interpret natural language and answer several fields from one turn. Preserve names; transliterate when the form requires Latin script and ask for spelling confirmation. Do not translate proper names literally.
- Interpret "नहीं, छठी नहीं, सातवीं" as a correction of the class field, not a new unrelated answer. Keep other fields unchanged. Show the update and allow undo.
- Context matters: if someone currently lives in Jaipur and will move to Pune, populate separate fields where they exist. If the form has only an ambiguous Address field, ask which address is requested.
- Never invent missing dates, phone numbers, PIN codes, birth dates, qualifications, or addresses. Ask about ambiguous dates such as 04/05/2015 rather than silently selecting a convention. A vague month without a year is not a complete date.
- A short invalid phone number gets a clarification, not guessed digits. Phone values are strings. Read digits individually for confirmation. Do not hardcode every imported form to Indian phone or PIN formats; apply the form's known constraints.
- Preserve the previous accepted value if a proposed replacement fails validation. Do not let a schema-invalid model response corrupt state.
- Support "What does this mean?", "Repeat", "I don't know", "Skip for now", "Read my answers", and "Change my answer". Explain fields simply without inventing official advice. Required skipped fields remain unresolved; optional fields may remain blank.
- Confirmation must work by voice as well as by clicking. Present a final spoken and visible review, including names, dates, and contact details. Any later edit invalidates final approval until reviewed again.
- Distinguish unanswered, answered, needs confirmation, optional skipped, and manual step. Completion is derived from state, not a model's claim that the form is complete.
